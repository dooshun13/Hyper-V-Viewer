# Hyper-V Viewer Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the renamed Eviewer code base into a read-only Hyper-V host troubleshooter whose main feature answers "why did this VM restart or power off, and where has it been over the last 7 days?"

**Architecture:** Keep Eviewer's layers (Core → System/Rules → App). Add a resource guard and a safety test for production hosts, Hyper-V channels and troubleshooters, a read-only WMI VM inventory, and a **VM story engine** (embedded lifecycle catalog + pure story builder + reader service) shown on a new VMs screen and a per-VM story screen.

**Tech Stack:** .NET 10, C#, WPF + WPF-UI, CommunityToolkit.Mvvm, `System.Diagnostics.Eventing.Reader` + `wevtapi.dll`, `System.Management` (WQL `SELECT` only), xUnit. CI: `.github/workflows/ci.yml` on `windows-latest`.

**Spec:** `docs/superpowers/specs/2026-11-13-hvviewer-v1-design.md`. Rules: `CLAUDE.md`. Each task is GitHub Issue `#N` (label `plan`); finish a task with `Closes #N` in the commit message.

## Global Constraints

- Viewer only: never clear, write or reconfigure event logs; never write the registry; never start/stop/change services, tasks, drivers or settings.
- Hyper-V and cluster WMI: WQL `SELECT` only. No WMI method calls. Never `Win32_Product`.
- Process priority `BelowNormal`; at most **2** parallel message-formatting threads.
- Every scan and search stops at **500,000** events or **1 GB** managed memory (`GC.GetTotalMemory(false)`), keeps partial results, and reports the reason in the skipped list.
- Every event query has a time range.
- Files written: only `%AppData%\HvViewer\HvViewer.settings.json` and exports saved through a Save dialog.
- Match events by provider + event ID + log internal name, never by message text. Level read as a number.
- UI English only; Windows' messages shown as formatted (may be French).
- Hints appear **only when certain** (spec §6.3). Hint texts are ours, short and plain, never copied from Microsoft.
- `TreatWarningsAsErrors` is on (`Directory.Build.props`): new code must build warning-free.
- Tests that need real logs or WMI use `[WindowsFact]` (`tests/HvViewer.Tests/WindowsFactAttribute.cs`).
- Core, System and Rules never reference WPF. App holds no business logic.

## Review Focus

- **VM ID case and braces:** Hyper-V writes the VM ID upper-case (`<VmId>106925A8-…</VmId>`), WMI gives it lower-case. Story matching must be case-insensitive and ignore braces. Test in Task 10.
- **Limit reached mid-story:** a busy host hits 500,000 events while building a story; the story shows what was read plus the limit reason, never an exception. Test in Task 11.
- **Standard user / missing log:** Worker-Admin access denied or a channel not installed; the story is still built from the other logs and the skipped list names the log. Test in Task 11.
- **VM state unknown before a host event:** a host restart with no earlier start event for the VM in range is shown, without a hint. Test in Task 10.
- **Time zone:** story and VM list times follow the Settings choice (this PC / UTC) via `AppState.FormatTime`. Test in Task 14.
