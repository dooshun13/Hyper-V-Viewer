# Eviewer v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Eviewer v1, a portable, read-only Windows event viewer with a 24 h dashboard, powerful search, event explanations and 11 troubleshooters, safe to run on production machines.

**Architecture:** Four libraries plus a WPF app. `Eviewer.Core` reads, filters and searches events, through `IEventSource` with a native `wevtapi` reader and a managed reader. `Eviewer.System` reads machine info and health from the registry and other read-only sources. `Eviewer.Rules` loads the JSON troubleshooter rules and builds the dashboard. `Eviewer.App` (WPF + WPF-UI, MVVM) contains screens only. Dependencies: App → Rules, System → Core.

**Tech Stack:** .NET 10 SDK, C# (latest), WPF, WPF-UI (lepoco, latest 4.x), CommunityToolkit.Mvvm (latest 8.x), System.Diagnostics.EventLog, xUnit, GitHub Actions on `windows-latest`.

**Spec:** `docs/superpowers/specs/2026-11-11-eviewer-v1-design.md`. Read it with this plan. `CLAUDE.md` holds the non-negotiable rules.

## Global Constraints

- Supported OS: Windows 10/11, Windows Server 2016, 2019, 2022, 2025, Windows Server 2012 R2. x64.
- Libraries (`Eviewer.Core`, `Eviewer.System`, `Eviewer.Rules`) target `net10.0` and mark Windows-only types `[SupportedOSPlatform("windows")]`. `Eviewer.App` targets `net10.0-windows` with `UseWPF`.
- Publish: self-contained, `win-x64`, `PublishReadyToRun=true`, **never** `PublishSingleFile`. Output is a folder, zipped as `Eviewer-<version>-win-x64.zip`.
- Read-only: no event log clear or config writes, no registry writes, no services, tasks or drivers, no system settings, no `Win32_Product`, no process launching except opening a clicked URL, no network access.
- Files written: only `Eviewer.settings.json` (next to the exe, or `%AppData%\Eviewer` after the user chooses it) and export files the user saves through a Save dialog. Nothing in temp, no logs or caches on disk. `--no-save` writes no settings.
- Resources: process priority BelowNormal; reader threads in background mode; at most 2 parallel log readers; every query has a time range; event limit default 500,000.
- Rules match on provider name (or event source name) + event ID + log internal name only. Level read as a number.
- UI language English only. Dates in query text and inputs: ISO `yyyy-MM-dd HH:mm:ss`.
- Performance (spec §7): window usable < 2 s; 24 h dashboard < 10 s; filter loaded data < 200 ms; text search over ~50,000 events < 5 s; memory < 300 MB typical.
- Batch size for native reads and text formatting: 256.

## Decisions this plan makes (spec gaps)

1. **Time zone switch:** v1 has no remote servers, so "this PC" and "the server" are the same machine. v1 offers **Local** and **UTC**.
2. **Export files** are a second permitted write, only through a user-driven Save dialog. Task 1 updates `CLAUDE.md` rule 2 to say so.
3. **Grouping:** "same message template" = same (log, provider, event ID). Events group when **consecutive in time order** with the same key and at most 2 minutes apart, matching the mockup (23:41 ×9, then 23:44 ×3 as a separate group).
4. **Rule files carry a `log` per event**; a troubleshooter's log list is derived from its events.
5. **Docs links** use a Microsoft Learn search URL (`https://learn.microsoft.com/search/?terms=<provider>%20event%20<id>`) unless the author verified a specific page, so links never point at made-up pages.
6. **Dashboard scan:** for the current period, each dashboard log is read in full (basic fields only), except **Security**, which is read only for rule event IDs. For the previous 7 days, only events with Level ≤ 3 or rule IDs are read.
7. **"Before the restart" anchor:** take the newest Kernel-Power 41 or EventLog 6008 in the period, then the EventLog 6005 at or before it (the boot). The anchor is the newest event of any level, in the dashboard logs, logged before that 6005. The window is [anchor − 15 min, anchor], listing Level ≤ 3 events. This finds what happened just before the crash, not just before the boot record.
8. **Health thresholds the spec leaves open:** last update Warning > 35 days, Problem > 60 days (from the newest WindowsUpdateClient 19 event); certificates Warning ≤ 30 days, Problem ≤ 7 days, already-expired ones ignored; time sync Warning if any Time-Service 36 in the last 24 h, OK if a 35 or 37 in the last 7 days, otherwise Unknown.
9. **Tests:** `tests/Eviewer.Tests` (`net10.0`, runs on Linux and Windows) for the libraries, plus `tests/Eviewer.App.Tests` (`net10.0-windows`, Windows only) for view-models. Tests that touch real logs use `[WindowsFact]` and skip elsewhere.
10. **XPath limits:** more than 20 include or exclude IDs are filtered in-process instead of in XPath.

## Review Focus

1. **Standard user on a server:** the Security log is denied. The Logons tile must show "Run as administrator to include", **not 0**, and the scan must finish. *(Task 18 test `Tile_AllLogsSkipped_IsUnavailableNotZero`; Task 11 test `Run_AccessDeniedLog_IsSkippedAndScanContinues`.)*
2. **A huge or very busy log** (millions of events): the event limit stops loading, keeps partial results, and the UI stays responsive. *(Task 11 test `Run_BudgetExhausted_StopsWithLimitReached`.)*
3. **Events whose publisher isn't installed:** formatting returns null; search in Message mode must not crash, and the row falls back to raw data. *(Task 8 test `FormatMessage_UnknownPublisher_ReturnsNull`; Task 11 test `Run_TextSearch_NullMessage_FallsBackToEventDataText`.)*
4. **Bad user input:** From after To, an invalid regex, a catastrophic regex, quotes in source names. These give clear validation errors, a 100 ms regex timeout, and escaped XPath. *(Task 2 `Validate_*`, Task 3 `Build_EscapesQuotes`, Task 5 `Regex_Catastrophic_TimesOutAsNoMatch`.)*
5. **Daylight-saving time and time zones:** a custom range typed in Local time across a DST change must convert to the right UTC instants, and displayed times must follow the Local/UTC switch. *(Task 4 test `Parse_FromTo_DstGap_ConvertsWithZoneRules`.)*
